# RoboCart 안정화 + 사람 인식 개선 계획서

작성일: 2026-06-15

## 0. 현재 상황 요약

라파(192.168.0.38) ↔ 노트북 WSL(192.168.0.39) ↔ 브라우저(localhost:8090) 파이프라인은
구축 완료. 5층 공유기로 옮긴 뒤 DDS 통신은 19.5fps로 안정적. 그러나 두 부류의 문제가 남음:

1. **프로세스 관리 불안정** — 노드가 중복 실행되어 구독 실패 (확정 원인)
2. **사람 인식 품질 낮음** — 등록 부실 + 알고리즘 한계

---

## A. 이슈 진단 (확정된 원인)

### A-1. 좀비 프로세스 누적 → 구독 실패
- 현재 WSL에 `register_node ×2`, `tracker_node ×2`, `web_stream ×2` 동시 실행 중.
- 같은 토픽을 여러 노드가 발행/구독 → DDS participant 충돌, 포트(8090) 점유.
- 증상: 단순 구독자는 영상 수신(145회/8초)되는데 `register_node`/`web_stream`은 0프레임.
- **근본 원인**: 수동 실행/종료 + 셸 따옴표 문제로 `kill`/`pkill`이 반복 실패해
  죽은 줄 알았던 노드가 계속 살아 누적됨.

### A-2. 등록 품질 부실
- 4회 등록했으나 뒷모습이 매번 `방향=front`로 잘못 라벨 → 뒷면 프로필 부정확.
- 원인: ① 화면을 못 봐서 사용자가 안 돌았음(화면은 이제 수정됨)
  ② 등록 로직이 **방향과 무관하게 3초 후 무조건 촬영**(뒤돌았는지 검증 안 함)
  ③ 초기 등록은 저화질(q30, 320~480)에서 진행됨.

## C. 사람 인식 개선 계획

### C-1. 등록 품질 향상 (효과 가장 큼, 난이도 낮음)
- [ ] **방향 검증 촬영**: 정면 단계는 `방향==front`, 뒷면 단계는 `방향==back` 일 때만
      카운트다운/촬영. 안 맞으면 "더 돌아주세요" 안내 → 뒷면 프로필 정확도 ↑.
- [ ] **고화질 등록**: 640×480 q60 이상 고정 (현재 카메라 설정 그대로 사용).
- [ ] **다중 샷 평균**: 각 방향 1장 → 3~5장 평균 임베딩으로 안정화.
- [ ] **측면(side)도 등록**: front/back만이 아니라 좌/우 측면 추가 → 회전 시 강건.
- [ ] **등록 화면 가이드**: 실시간으로 감지된 방향/거리/밝기를 표시해 사용자가 맞추게.

### C-2. 인식 알고리즘 강화 (효과 큼, 난이도 중)
- [ ] **전용 Person-ReID 모델로 교체**: 지금은 ImageNet 분류용 ResNet50(전이학습 안 함).
      → **OSNet(market1501/MSMT 학습)** 등 ReID 전용 모델로 바꾸면 사람 구분 정확도 급상승.
      (torchreid 라이브러리, 모델만 교체하면 임베딩 품질 ↑, 속도도 ResNet50보다 가벼움)
- [ ] **가중치 재튜닝**: 현재 ReID 0.55 / 색상 0.25 / 체형 0.15 / 위치 0.05.
      전용 ReID 적용 후 ReID 비중을 더 높이고 색상 의존 ↓ (옷 갈아입어도 추적되게).
- [ ] **임계값 데이터 기반 조정**: 등록자 vs 비등록자 점수 분포를 로깅해
      `MATCH_THRESHOLD`(0.77)·`REID_FLOOR`(0.50) 최적값 산출.
- [ ] **조명/거리 정규화**: 색상은 이미 V채널 제외(조명 강건). crop 정규화 추가 검토.

### C-3. 추적 안정성 (효과 중, 난이도 중)
- [ ] **멀티오브젝트 트래커 결합**: ByteTrack/OC-SORT로 사람마다 ID 부여 →
      ReID는 "어느 ID가 등록자인지"만 가끔 판정, 사이엔 트래커가 위치 유지.
      → 프레임 스킵·잠깐 가림에 강하고, ReID 호출을 줄여 **프레임율도 개선**.
- [ ] **칼만 필터**로 bbox 보간 → 검출 사이 부드러운 추적.

### C-4. 프레임율 (인식과 직결)
- [ ] **표시/인식 분리**: 영상은 15fps로 흘리고 인식 박스는 5fps 갱신.
- [ ] **ReID 스로틀**: 매 프레임 → N프레임마다 (C-3 트래커와 결합 시 자연 해결).
- [ ] GPU는 이 노트북(Intel Iris Xe, NVIDIA 없음)에선 실효성 낮음 — 알고리즘 최적화로 대응.

## D. 우선순위 / 실행 순서

| 순위 | 작업 | 이유 | 난이도 |
|---|---|---|---|
| 1 | B-1 프로세스 일원화 | 지금 등록·추적을 막는 직접 원인 | 낮 |
| 2 | C-1 등록 품질(방향 검증+다중샷) | 인식 개선 효과 가장 큼, 코드 소량 | 낮 |
| 3 | C-2 ReID 모델 교체(OSNet) | 인식 정확도 근본 개선 | 중 |
| 4 | C-3 트래커 결합 | 추적 안정 + 프레임율 동시 개선 | 중 |
| 5 | C-4 표시/인식 분리 | 체감 부드러움 | 낮~중 |

**1단계(프로세스 일원화)부터 하면 곧바로 등록·추적이 정상 동작**하고,
그 위에서 2~5단계로 인식 품질을 끌어올리는 순서를 제안.
