# 등록 사용자 인식/추종 단계적 향상 계획 (2026-07-01)

> **대상 파일:** `OpenCV_2/v2/` — `ros_person_follower_nav2_v2.py` 를 기반으로 `_v3`, `_v4` … 순으로 신규 파일 추가

## 현재 구조 요약 (v2 기준)

```
인식: YOLOv8n-ONNX(검출) + OSNet-x0.25 ONNX(ReID) + HSV 색상 히스토그램
스코어: ReID 70% + 색상 25% + 위치 5%
방향: YuNet 얼굴 감지로 앞/뒤 판별 (활용도 낮음)
추적: KCF 보간 (DETECT_INTERVAL=5) + TrackingState 히스테리시스

추종: bbox 너비 → 거리 추정(핀홀) → linear.x P제어
      bbox 중심x 편차 → angular.z P제어
```

## 향상 우선순위 (효과 대비 비용 순)

### 인식 향상

| 순위 | 방법 | 이유 |
|------|------|------|
| 1 | ~~ReID x0.25 → x1.0~~ ✅ **v3 적용** | 스코어 70% 담당, 임베딩 품질 향상이 인식률에 직결 (x1.0 재등록 필요) |
| 2 | **YOLO n → n-Pose 교체** | 모델 크기 거의 동일, 체형 키포인트 추가 (MediaPipe 대체) |
| 3 | **YOLO n → s** | 검출률 향상, 부분 가림 개선 (추론 시간 증가 주의) |

> 방향별 임베딩 분리 등록은 **v2에서 이미 구현 완료**
> COLOR_FLOOR 0.30 → 0.15 **v2·v3 공통 적용** (light_features.py) — ReID 점수 높을 때 색상 게이트가 과도하게 차단하던 문제 수정

### 추종 향상

| 순위 | 방법 | 이유 |
|------|------|------|
| 1 | ~~LiDAR 방위각 거리 우선, bbox 너비 폴백~~ ✅ **v3 적용** | 카메라 핀홀 추정보다 정밀, ±15° 범위 유효값 중 최솟값 사용 |
| 2 | **YOLO-Pose 몸통 중심 → angular.z** | 팔 움직임에 흔들리는 bbox 중심보다 안정적 |
| 3 | **P → PD/PID 제어** | 진동/오버슈트 감소 |

## ✅ v3 상세 변경 내역 (2026-07-01)

### 추종 향상

| 항목 | v2 | v3 |
|------|----|----|
| 거리 측정 | bbox 너비 핀홀 추정 | LiDAR 방위각 ±15° 최솟값 우선, 폴백 bbox 너비 |
| 탐색 회전 | 없음 | 완전 유실 시 좌우 교대 회전 (0.15 rad/s, 3초 주기) |
| FOLLOW 연산 | 항상 실행 | FOLLOW 모드일 때만 YOLO/ReID 실행 |
| DETECT_INTERVAL | 5 | 8 (OSNet x1.0 연산 부하 보상) |

### 오인식 방지

| 항목 | 변경 | 효과 |
|------|------|------|
| `SEARCH_MATCH_THR` | 신규 0.70 | 탐색 중 임계값을 일반(0.72)보다 약간 낮게 유지 |
| 소프트매치 정지 기준 | 0.55 → **0.63** | 낮은 점수 타인이 회전을 멈추지 않음 |
| `SEARCH_CONFIRM_FRAMES` | 신규 **5** | 탐색 후 재인식 시 연속 5프레임 매칭 요구 (일반 3프레임 대비 엄격) |
| `_from_search` 플래그 | `TrackingState` 내부 추가 | 완전 유실 → 재인식 구간 자동 감지, confirm 수 자동 전환 |

### 재인식 향상 (유실 후)

| 항목 | 내용 |
|------|------|
| 탐색 중 임계값 완화 | `searching` 상태에서 0.72 대신 0.70 사용 (측면·역광 등 불리한 각도 보완) |
| 소프트매치 일시 정지 | 후보 스코어 0.63 이상이면 회전 멈추고 confirm 기회 부여 |
| confirm 프레임 구분 | 일반 추종 시작: 3프레임 / 탐색 후 재인식: 5프레임 |
| 탐색 회전 속도 | 0.3 → **0.15 rad/s** (프레임당 이동 각도 축소 → 등록자 놓칠 확률 감소) |
