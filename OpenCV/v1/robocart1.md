# 스마트 장바구니 로봇 등록 사용자 실시간 인식 기획서

> **처리 방식: 분산 처리** — `robocart_main.py` (VMware에서 실행)  
> 실제 구현은 아래 계획의 Phase별 파일 대신 `robocart_main.py` 단일 파일로 완성됨.

---

## 1. 프로젝트 개요

본 프로젝트는 고령자와 교통약자가 쇼핑 중 무거운 장바구니를 직접 끌고 다니지 않아도 되도록 돕는 스마트 장바구니 시스템을 목표로 합니다.  
기존 쇼핑 카트의 단순 수납 기능을 넘어, 사용자를 자동으로 따라오는 보조 기능의 기반이 되는 **등록 사용자 인식 기능**을 먼저 구현하고자 합니다.

이번 단계에서는 로봇 주행이나 ROS2 제어는 포함하지 않고,  
**처음 등록한 사람 1명만 카메라 영상에서 구분할 수 있는 인식 기능**에 집중합니다.

## 2. 핵심 목표

### 최종 목표

등록된 사용자 1명을 다른 사람들과 구분해 안정적으로 식별한다.

### 이번 단계 목표

1. 사용자를 등록할 때 앞모습과 뒷모습을 함께 저장한다.
2. 얼굴이 보이지 않아도 뒷통수, 체형, 옷 색상, 전체 실루엣으로 등록 사용자를 구분한다.
3. 여러 사람이 화면에 있어도 등록된 사람 1명만 선택해 표시한다.
4. ROS2 연동 없이 카메라 영상 기반 식별 결과까지만 구현한다.

## 3. 요구사항 정의

### 기능 요구사항

1. 최초 등록 시 한 사람의 앞모습과 뒷모습 데이터를 모두 수집할 수 있어야 한다.
2. 등록 데이터에는 얼굴뿐 아니라 체형, 의상 색상, 전신 특징을 함께 저장해야 한다.
3. 실시간 영상에서 사람 후보가 여러 명이어도 등록된 사람만 선택해야 한다.
4. 얼굴이 안 보이는 상황에서도 뒷모습 기반으로 같은 사람인지 판별해야 한다.
5. 등록되지 않은 사람은 추적 대상 후보에서 제외해야 한다.

### 비기능 요구사항

1. 등록 절차는 복잡하지 않아야 한다.
2. 실시간에 가깝게 동작할 수 있어야 한다.
3. 조명 변화, 사람 가림, 방향 전환에 어느 정도 견딜 수 있어야 한다.
4. 저장 데이터는 최소화하고 관리 가능한 구조여야 한다.

## 4. 인식 전략

### 왜 얼굴 인식만으로 부족한가

스마트 장바구니는 사람의 뒤를 따라가는 상황이 많기 때문에, 실제 운용 시 카메라에는 얼굴보다 **뒷모습**이 더 자주 들어옵니다.  
따라서 얼굴 인식만으로는 등록 사용자를 안정적으로 식별하기 어렵습니다.

### 제안 전략

등록 시점과 인식 시점 모두에서 다음 특징을 함께 사용합니다.

1. 앞모습 특징
2. 뒷모습 특징
3. 체형 비율
4. 옷 상하의 대표 색상
5. 전신 실루엣 또는 사람 임베딩 특징

즉, 이번 시스템은 단순 얼굴 인증이 아니라  
**단일 사용자 재식별(Person Re-Identification, ReID) 기반 인식 구조**로 설계합니다.

## 5. 등록 방식

### 등록 시 수집할 데이터

사용자 1명을 등록할 때 아래 정보를 함께 확보합니다.

1. 앞모습 전신 이미지
2. 뒷모습 전신 이미지
<!-- 3. 좌측 또는 우측 측면 이미지 — 실제 구현에서 제외 (앞/뒤만 사용) -->
4. 상의/하의 대표 색상 정보
5. 키 대비 어깨너비, 몸통 비율 같은 체형 정보

### 등록 절차

1. 사용자가 카메라 앞 정면에 선다.
2. 앞모습을 1장 촬영한다.
3. 뒤로 돌아서 뒷모습을 1장 촬영한다.
4. 촬영한 이미지에서 전신 박스, 색상 특징, 체형 특징, 임베딩 특징을 추출한다.
5. 최종 등록 데이터로 저장한다.

### 등록 데이터 예시

```json
{
  "user_id": "owner_001",
  "front_features": ["..."],
  "back_features": ["..."],
  "body_shape_features": {
    "shoulder_ratio": 0.31,
    "torso_ratio": 0.42
  },
  "color_profile": {
    "top_rgb": [52, 78, 120],
    "bottom_rgb": [40, 40, 45]
  },
  "registered_at": "2026-06-09T12:00:00"
}
```

## 6. 실시간 인식 방식

### 전체 흐름

```text
[카메라 입력]
    ↓
[사람 검출]
    ↓
[후보별 전신 특징 추출]
    ↓
[등록 사용자 특징과 유사도 비교]
    ↓
[가장 유사한 1명 선택]
    ↓
[임계값 이상이면 등록 사용자로 판정]
    ↓
[화면에 표시]
```

### 후보별 비교 항목

1. 전신 임베딩 유사도
2. 상의 색상 유사도
3. 하의 색상 유사도
4. 어깨너비와 키 비율
5. 몸통 길이 비율
6. 이동 연속성

### 최종 판정 방식 (가중치)

1. 전신 임베딩(ReID): 50%
2. 상하의 색상: 25%
3. 체형 비율: 15%
4. 위치 연속성: 10%

## 8. 방향 판별 로직

### 방향 판별 기준

1. 얼굴 검출 여부
2. 어깨/귀/코 랜드마크 가시성
3. 신체 랜드마크 배치

### 활용 방식

1. 앞모습으로 판정되면 front feature와 비교
2. 뒷모습으로 판정되면 back feature와 비교
3. 측면이면 front/back 둘 다 비교해 더 높은 점수 사용

## 9. 위험요소와 대응 방안

### 위험요소 1. 옷을 갈아입으면 인식률 저하
- 체형 특징 비중 유지
- 색상 외 전신 임베딩도 함께 사용
- 필요 시 재등록 기능 제공

### 위험요소 2. 비슷한 체형과 비슷한 옷을 입은 사람 존재
- ReID 특징을 주요 기준으로 사용
- 앞/뒤 특징을 분리 비교

### 위험요소 3. 조명 변화
- HSV 기반 색상 특징 사용

### 위험요소 4. 사람 가림
- 연속 프레임 기반 보정
- 잠시 유실 시 직전 후보 유지

### 위험요소 5. 사용자 유실
- 등록된 사용자 유실 시 다른 사용자를 등록된 사용자로 인식하지 않고 대기 후 재탐색
